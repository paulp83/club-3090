No pair differed significantly (best McNemar p = 0.25). Three findings shaped the next step:

  1. The task set split three ways. 6 tasks every config solved, 4 tasks separated configs, and 10 tasks no config solved. Ten all-fail tasks is a warning sign, not proof of a hard bench.
  2. 8 of those 10 were unfair as written. Reading the failures across all configs showed the hidden tests checked something the text never stated: an exact CLI (catalog.sh rename/update, #1209), a new function name (gpu_vram_report_lines, #1571), unmentioned edge cases (#1518, #1555, #1610, #1612), a plan line (#1564), or one exact sentence the agents had paraphrased correctly (#1621). Only #1174 and #1510 were genuine misses. Step-4 screening missed them because it only read failure messages printed before the fix.
  3. GLM ran far faster than expected: about 13 minutes per task, level with Strata, not the 30–60 the quality packs suggested. Agent turns are short, so decode speed matters less than in long-answer packs.

No regressions in 80 runs; one run hit the 100-step limit. What the details say that the solve rate can't:

  1. Only 6 tasks separate the configs. 11 were solved by all four and 3 by none (#1174, #1510, #1555). The best pairwise gap, Strata IQ4_XS vs ThinkingCap and vs GLM IQ4_XS, is 4 tasks to 0 (McNemar p = 0.12): close, not significant. The Interface sections overshot: 5 of the 8 revised tasks went from solved by nobody to solved by everyone (#1209, #1564, #1571, #1610, #1621), so they stopped separating configs the other way.
  2. Flash Next wins by persistence. The tasks only it solved are the long ones: #1588 (100 steps, 44 min), #1556 (26 min), and #1573 with avar6 (25 min). Its failures are real attempts. ThinkingCap's failures end in 2.5 to 9 minutes, which reads as giving up or submitting a confident wrong fix.
  3. ThinkingCap leads on throughput. It answers 3 to 4 times faster per turn (7 s/step vs 19 to 28) while writing the most tokens (about 23K on the tasks everyone solved, vs 8K to 19K), so it solves 7.3 tasks per agent-hour, twice Flash Next's 3.5, with 4 fewer solves. A check-and-retry loop gets more done per hour with ThinkingCap; Flash Next gets more of the hard ones right first time.
  4. GLM is terse and precise. The fewest tokens per step (290 to 315 vs 500 to 750) and the best file localization (0.93 to 0.96); avar6 alone solved #1204, the hardest task here (93 steps). Slower decode holds it to about 2.4 solved per hour. Its two quants sit one task apart, as in the quality packs.
  5. On equal work (the 11 tasks all four solved), median time is 2.7 min for ThinkingCap, 8.2 to 8.6 for GLM and 11.0 for Flash Next, at similar step counts (23 to 33). The time gap is per-turn model speed, not strategy.

Harness and scoring fixes found along the way (all applied before the numbers above, or re-scored):

  • The SWE-bench config sets BASH_ENV=/root/.bashrc. Run as a non-root user, every command printed a permission error, which broke the submit step. Dropped BASH_ENV, set HOME=/tmp.
  • Scoring the agent's submitted text made the score depend on the submit ritual. Switched to scoring the working tree.
  • Some tests print only failures plus a PASS: N FAIL: M total. The check counter skipped totals, so a 12-of-15 near miss scored 0.0. It now uses the total; the references were recounted and finished runs re-scored (--rescore).
  • One config briefly ran two copies of itself at once (a restarted chain left a run behind). The second run overwrote every task, so results are single-run, but the first few tasks' times are slightly inflated.
  • A process check using pgrep -f <pattern> matched the checking shell's own command line and reported a finished run as still going. Check result files, not process names.
  • Strata listens on 127.0.0.1 by default, which the club quality harness's sandboxes can't reach; serve it on --host 172.17.0.1 for any containerised harness.
